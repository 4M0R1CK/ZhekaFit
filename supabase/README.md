# Supabase: схема и эксплуатация

## SQL Editor

Открой Supabase Dashboard → **SQL Editor**, вставь `create_database.sql` и запусти целиком. Это идемпотентный скрипт установки и ремонта существующей схемы: он не удаляет таблицы и строки. Он создаёт/добавляет схему приложения, индексы, триггер создания профиля после регистрации, RLS-политики, транзакционное бронирование, RPC доступности мест и публичный bucket `club-media` с ограничением 10 MB.

В SQL нет seed-данных. Новые каталоги пустые и становятся видны посетителям только после публикации строк администратором. Публичному клиенту разрешено читать опубликованные каталоги и расписание, пользователь может читать и менять свой профиль, создавать заявку на опубликованный тариф и читать/отменять свои записи. Создавать бронирование напрямую запрещено: нужно вызывать `book_class_session`, где в транзакции проверяется статус занятия, публикация, повторная запись и вместимость.

`migrations/202611130001_initial_schema.sql` содержит ту же актуальную схему для CLI. Если схема создавалась из SQL Editor, продолжай применять repair-скрипт там: `supabase db push` дополнительно требует корректной истории уже применённых миграций.

## Таблицы

- `profiles` — профиль, связанный с `auth.users`.
- `programs`, `trainers`, `program_trainers` — публичные программы и специалисты.
- `membership_plans`, `memberships` — опубликованные тарифы и заявки/абонементы.
- `class_sessions`, `bookings` — расписание и пользовательские записи.

## Контент и изображения

Клубные фотографии находятся в `assets/upload`. `npm run supabase:upload-assets` отправляет их в `club-media/site/` через серверный secret/service-role key. `npm run supabase:seed-content` добавляет программы, команды тренеров, тарифы, связи и расписание; обе команды безопасно повторять. Перед продажами замени предварительные суммы тарифов в `membership_plans` на утверждённые клубом. Фотографии профиля загружаются пользователем через браузер только в `profiles/<auth-user-id>/...`.

## Секреты и Auth

- Frontend: `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` в `.env.local`.
- Только административный скрипт: `SUPABASE_URL` и `SUPABASE_SECRET_KEY`. Допустим legacy `SUPABASE_SERVICE_ROLE_KEY`.
- Не помещай secret/service-role key в переменные `VITE_*` или браузерный код.
- Настрой разрешённые redirect URL в Supabase Auth для локального и production адресов.
